# Requirements Document

## Introduction
Zaim Lens におけるアカウント間履歴コピー & 一括編集 UI 機能に関する要件定義書です。  
ユーザーが複数の Zaim アカウント間で支出履歴を取得・比較し、レシート単位または個別品目単位で選択した上で、コピー先アカウントの出金元口座やカテゴリ・ジャンルを付け替えながら一括同期・コピーできるフロントエンドユーザーインターフェースを提供します。

## Boundary Context
- **In scope**:
  - コピー元アカウントおよび取得期間（クイック期間、月指定、カスタム範囲）の選択・入力フォームUI
  - 履歴データの非同期取得リクエストと取得中のローディング/スケルトン表示
  - 取得した履歴明細のレシート単位グループ化とアコーディオン展開・折りたたみUI
  - レシート単位および個別品目単位の選択チェックボックス、全選択/全解除ボタン、選択件数カウンターの連動UI
  - コピー先アカウントおよびコピー先出金元口座の選択UI
  - コピー内容確認モーダルにおける明細ごとのカテゴリ・ジャンル付け替え、およびレシートごとの出金元口座個別選択UI
  - コピー実行リクエスト、重複検知時の警告ダイアログ表示と強制コピー（force）再試行ハンドリング
  - コピー完了画面（成功レシート件数・品目数表示）および状態リセット/トップ復帰UI
- **Out of scope**:
  - バックエンド側での Zaim API 通信、OAuth 1.0a 認証、支出データ登録ロジック（`zaim-integration` 仕様の所掌）
  - レシート画像の OCR 解析および品目推論（`gemini-api-backend`, `receipt-workflow-ui` 仕様の所掌）
- **Adjacent expectations**:
  - バックエンド（`zaim-integration`）から有効なアカウント一覧、マスタデータ（カテゴリ・ジャンル・口座）、および履歴データが提供されること
  - クライアントのユーザー認証（Firebase Authentication）が確立されていること

## Requirements

### Requirement 1: 履歴取得条件の設定とアカウント選択
**Objective:** As a ユーザー, I want コピー元アカウントと取得期間を指定して支出履歴を取得したい, so that コピー対象の明細を一覧化できる

#### Acceptance Criteria
1. When ユーザーがコピー元アカウントおよび取得期間（今月/先月/過去1ヶ月/過去3ヶ月/月指定/カスタム範囲）を選択して履歴取得ボタンを押下したとき, the History Copy UI shall 指定条件でバックエンドへ支出履歴取得を要求し、ローディング表示を行う
2. If ユーザーがコピー元アカウント未選択の状態で履歴取得を実行したとき, the History Copy UI shall 警告通知を表示して処理を中断する
3. If 期間指定でカスタム範囲が選択され、開始日が終了日より後であるとき, the History Copy UI shall 入力バリデーションエラーを通知して処理を中断する
4. When ユーザーがコピー元アカウントを変更したとき, the History Copy UI shall 取得済み履歴および選択状態をクリアし、コピー先アカウント選択肢から同一アカウントを除外して再構築する

### Requirement 2: 履歴一覧のアコーディオン表示と選択操作
**Objective:** As a ユーザー, I want 取得した履歴をレシート単位で確認し、コピー対象を柔軟に選択したい, so that 必要な明細のみを抽出してコピーできる

#### Acceptance Criteria
1. When 履歴データの取得が完了したとき, the History Copy UI shall 支出明細をレシート識別子（または単一支出）ごとにグループ化し、日付・店名/カテゴリ・合計金額を表示するアコーディオン一覧としてレンダリングする
2. When ユーザーがアコーディオンヘッダーを押下したとき, the History Copy UI shall 当該レシートに含まれる明細品目一覧（品名・金額・カテゴリ・コメント）の展開/折りたたみ表示を切り替える
3. When ユーザーがレシート単位の親チェックボックスを操作したとき, the History Copy UI shall 当該レシートに含まれる全品目の選択状態を一括で連動更新し、選択件数表示を更新する
4. When ユーザーが個別品目のチェックボックスを操作したとき, the History Copy UI shall 親チェックボックスを全選択・未選択・一部選択（不確定）状態に連動更新し、選択件数表示を更新する
5. When ユーザーが全選択ボタンを押下したとき, the History Copy UI shall 一覧内の全明細の選択状態を一括でトグルし、ボタン表示を「全選択」または「全解除」に切り替える

### Requirement 3: コピー先アカウントおよび出金元口座の指定
**Objective:** As a ユーザー, I want コピー先アカウントと記録用の出金元口座を指定したい, so that 正しい家計簿と口座に支出を記録できる

#### Acceptance Criteria
1. When ユーザーがコピー先アカウントを選択したとき, the History Copy UI shall コピー先アカウントの有効な出金元口座一覧およびカテゴリマスタを取得して選択肢を更新する
2. While コピー対象品目が1件以上選択されているとき, the History Copy UI shall 確認画面へ進むボタンを活性化し、選択中のレシート件数および品目数を表示する
3. While コピー対象品目が0件のとき, the History Copy UI shall 確認画面へ進むボタンを非活性化する

### Requirement 4: コピー内容の確認とカテゴリ・口座付け替え
**Objective:** As a ユーザー, I want コピー実行前に明細を確認し、カテゴリや出金元口座を調整したい, so that コピー先アカウントの分類体系に合わせた家計簿を作成できる

#### Acceptance Criteria
1. When ユーザーが「確認画面へ進む」を押下したとき, the History Copy UI shall 選択された明細のみを抽出したコピー内容確認モーダルを表示する
2. When 確認モーダル内でユーザーが特定品目のカテゴリを変更したとき, the History Copy UI shall コピー先アカウントのマスタデータに基づいて対応するジャンル選択肢を動的に再生成する
3. Where コピー先出金元口座の一括設定値が選択されている場合, the History Copy UI shall 各レシートのデフォルト出金元口座として反映し、レシートごとの個別指定も可能とする

### Requirement 5: コピー実行・重複検知ハンドリング・完了表示
**Objective:** As a ユーザー, I want 設定した明細を一括でコピーし、重複登録の警告を確認しながら安全に完了させたい, so that 正確にデータ同期を完了できる

#### Acceptance Criteria
1. When ユーザーが確認モーダルで「確定してコピー実行」を押下したとき, the History Copy UI shall 確認モーダルを閉じ、編集されたカテゴリ・ジャンル・口座設定を含むペイロードでバックエンドへコピー実行を要求し、ローディング表示を行う
2. If コピー実行レスポンスで重複候補の存在警告が返却されたとき, the History Copy UI shall ユーザーに強制コピーを実行するか確認するダイアログを表示する
3. When 重複確認ダイアログでユーザーが承認（OK）したとき, the History Copy UI shall 強制登録フラグを有効にしてコピー実行を再試行する
4. When コピー実行が正常（または一部成功）に完了したとき, the History Copy UI shall コピー完了画面を表示して成功レシート件数および品目数を通知し、設定パネルを非表示にする
5. When ユーザーが完了画面で「トップに戻る」を押下したとき, the History Copy UI shall 履歴コピー機能の入力・選択状態を初期化して初期設定画面を表示する
